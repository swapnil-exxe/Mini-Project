# Functional Requirements

Functional requirements describe the core capabilities and interactions that the system must support for each user role.

## User Roles
1.  **Student (Junior/Reader)**
2.  **Contributor (Senior/Alumni)**
3.  **Administrator (TPO/Faculty/Moderator)**

---

## Requirements by Role

### 1. Student (Junior / Reader)
*   **FR-1.1**: Browse the landing page, branch landing page, and dashboard.
*   **FR-1.2**: Search placement stories using free-text keywords (student name, company, job role).
*   **FR-1.3**: Filter placement stories by Branch, Company, Year, and Role.
*   **FR-1.4**: View full senior profiles, including their chronological 4-year stories.
*   **FR-1.5**: View and download resumes linked to placement profiles.
*   **FR-1.6**: Browse study folders (DSA, Core CS, Web Dev, System Design) and open educational links/materials.
*   **FR-1.7**: View student achievements and hackathon details.

### 2. Contributor (Senior / Alumni)
*   **FR-2.1**: Onboard and create a profile specifying Name, Email, Branch, Passing Year, and CGPA.
*   **FR-2.2**: Submit a placement story by filling out prompt-based text fields (Years 1-4, preparation strategy, interview experience).
*   **FR-2.3**: Upload/link a PDF resume and paste study material links.
*   **FR-2.4**: Manage their profile and view their past submissions.

### 3. Administrator (Moderator)
*   **FR-3.1**: Log in to the administrative portal.
*   **FR-3.2**: View a dashboard summary of system statistics (pending reviews, active stories).
*   **FR-3.3**: Access a review queue of pending placement stories and pending resources.
*   **FR-3.4**: Approve submissions (making them live) or reject them with reasons.
*   **FR-3.5**: Create and manage study folders.
