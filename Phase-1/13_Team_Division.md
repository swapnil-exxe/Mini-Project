# Team Division

This document outlines the allocation of responsibilities and development roles for the three members of the Mini Project team.

---

## Individual Development Responsibilities

### Member 1: Frontend Developer (Placeholder Name)
*   **Primary Tasks**:
    *   Design and implement the UI/UX based on the editorial storytelling theme.
    *   Develop reusable React components (`Navbar`, `StoryCard`, `JourneySection`, etc.).
    *   Implement client-side routing and page templates.
    *   Manage application state for mock data search and filtration.
    *   Ensure responsiveness across mobile, tablet, and desktop viewports.

### Member 2: Backend Developer (Placeholder Name)
*   **Primary Tasks**:
    *   Design and develop the RESTful API using Node.js and Express.
    *   Implement authentication and authorization middleware (JWT tokens).
    *   Create secure api routes for user signup, logins, story submission, and moderation.
    *   Integrate validation libraries to filter request parameters and secure file upload streams.

### Member 3: Database Developer (Placeholder Name)
*   **Primary Tasks**:
    *   Design the MongoDB collections structure and schema relationships.
    *   Configure MongoDB Atlas cloud instances and network configurations.
    *   Develop Mongoose models and data validation schemas.
    *   Write database queries, aggregations, and indices to support searches and filters.

---

## Shared Responsibilities (All Members)
To ensure project cohesion, the following tasks are split equally among all members:
*   **System Integration**: Linking the React frontend with Express API endpoints and MongoDB services (Phase 2).
*   **Quality Testing**:
    *   Conducting functional testing across routes and user permissions.
    *   Verifying design responsiveness on multiple viewports.
*   **Project Documentation**: Authoring planning reports, database designs, user flows, and diagrams.
*   **Deployment**: Running staging and production builds.
*   **Presentation**: Creating slides, preparing live demonstrations, and explaining system architecture to faculty reviewers.
